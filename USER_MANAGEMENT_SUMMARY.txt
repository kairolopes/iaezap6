ENDPOINTS SUMMARY
================================================================================

1. GET /api/admin/users
   Purpose: List all users in the authenticated user's company
   Auth: Bearer token required
   Role: admin or owner
   Query: role, status, search, limit, offset
   Returns: User list with pagination info

2. PUT /api/admin/users/{id}/role
   Purpose: Change a user's role
   Auth: Bearer token required
   Role: admin or owner
   Body: { "role": "admin"|"member"|"viewer" }
   Returns: Updated user object
   Rules:
     - Cannot change own role
     - Admin cannot change owner role
     - Cannot demote last owner

3. DELETE /api/admin/users/{id}
   Purpose: Remove user from company (soft delete)
   Auth: Bearer token required
   Role: admin or owner
   Returns: Confirmation with user ID
   Rules:
     - Cannot remove yourself
     - Admin cannot remove owner
     - Cannot remove last owner
     - Data preserved (soft delete)

================================================================================
ROLE HIERARCHY
================================================================================

Owner (Level 4)
  ├─ Full access to all company features
  ├─ Can manage: All users (owner, admin, member, viewer)
  └─ Cannot be demoted if last owner

Admin (Level 3)
  ├─ Administrative access
  ├─ Can manage: Admin, member, viewer users
  ├─ Cannot manage: Owner users
  └─ Cannot promote users to owner

Member (Level 2)
  ├─ Standard access
  ├─ Cannot manage: Any users
  └─ Can view: Company resources

Viewer (Level 1)
  └─ Read-only access to shared resources

DATABASE SCHEMA REQUIRED
================================================================================

USERS TABLE:
  id UUID PRIMARY KEY
  company_id UUID (foreign key to companies)
  email VARCHAR
  full_name VARCHAR
  display_name VARCHAR
  role user_role (enum: owner, admin, member, viewer)
  status VARCHAR (enum: active, inactive, invited, suspended)
  email_verified BOOLEAN
  last_login_at TIMESTAMP
  created_at TIMESTAMP
  updated_at TIMESTAMP
  deleted_at TIMESTAMP (for soft delete)

AUDIT_LOGS TABLE:
  id UUID PRIMARY KEY
  company_id UUID
  user_id UUID
  action VARCHAR
  entity_type VARCHAR
  entity_id UUID
  old_values JSONB
  new_values JSONB
  ip_address VARCHAR
  user_agent TEXT
  created_at TIMESTAMP

REQUIRED INDEXES:
  - idx_users_company_id (for filtering)
  - idx_users_company_role (for role queries)
  - idx_users_company_email (for search)
  - idx_audit_logs_company_id (for audit trail)

USAGE EXAMPLES
================================================================================

LIST USERS:
  curl -X GET "http://localhost:3000/api/admin/users" \
    -H "Authorization: Bearer <token>"

CHANGE ROLE:
  curl -X PUT "http://localhost:3000/api/admin/users/{id}/role" \
    -H "Authorization: Bearer <token>" \
    -H "Content-Type: application/json" \
    -d '{"role": "admin"}'

REMOVE USER:
  curl -X DELETE "http://localhost:3000/api/admin/users/{id}" \
    -H "Authorization: Bearer <token>"

FILTER BY ROLE:
  curl -X GET "http://localhost:3000/api/admin/users?role=admin" \
    -H "Authorization: Bearer <token>"

SEARCH BY EMAIL:
  curl -X GET "http://localhost:3000/api/admin/users?search=john" \
    -H "Authorization: Bearer <token>"

PAGINATION:
  curl -X GET "http://localhost:3000/api/admin/users?limit=20&offset=0" \
    -H "Authorization: Bearer <token>"

PERFORMANCE NOTES
================================================================================

List Users Query:
  - Uses indexed columns (company_id, role, email)
  - Pagination prevents large result sets
  - Default limit 50, max 100 users per request
  - Search uses ILIKE (case-insensitive)

Role Change Query:
  - Single UPDATE query per request
  - Validates hierarchy before update
  - Atomic operation
  - Audit log created after success

Remove User Query:
  - Single UPDATE query (soft delete)
  - Sets both deleted_at and status
  - Audit log created after success
  - No cascade deletes

Recommended Indexes:
  - (company_id) on users table
  - (company_id, role) on users table
  - (company_id, email) on users table
  - (company_id, created_at DESC) on audit_logs

Cache Strategy:
  - Cache user list with 5-minute TTL
  - Invalidate on role change
  - Cache permissions in JWT token
  - Consider Redis for frequently accessed data

SUPPORT & TROUBLESHOOTING
================================================================================

COMMON ISSUES:

401 Unauthorized:
  - Check token is not expired
  - Verify token format (Bearer prefix)
  - Re-login to get new token
  - Check JWT secret in .env

403 Forbidden:
  - Check user role (must be admin or owner)
  - Verify not trying to modify yourself
  - Check target user role
  - Verify users in same company

404 Not Found:
  - Check user ID is valid UUID
  - Verify user exists in database
  - Confirm user not deleted
  - Check user in correct company

500 Internal Error:
  - Check database connection
  - Verify Supabase credentials
  - Check server logs
  - Restart development server

DEBUGGING:

Enable logs:
  - Add console.log in route handlers
  - Check browser DevTools Network tab
  - View Supabase logs
  - Check server stdout/stderr

View audit trail:

  - Filter by company_id and date
  - Check old_values and new_values fields

Performance:
